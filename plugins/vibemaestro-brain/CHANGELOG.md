# Changelog of vibemaestro-brain

Newest first. Each `## <version>` is a public release, written from the change notes it ships; the first public release is 0.1.0.

## 0.3.0

Released together: vibemaestro-sdlc 0.4.0, vibemaestro-brain 0.3.0

- minor: The brain gains three kinds: goals in the left brain (`brain owner add --kind goal`, through the dialog, with the owner's words, what done means, a not-doing line, a review day and a scope), and focus and requests in the right brain (`brain op add --kind focus|request`, each with the owner's words, stored whole and never rewritten; a focus points to a goal and orders Next, a request may carry a due day named from 7 days before and closes only with a pointer). String 1 opens with a precedence line (the owner's newer word, then SOUL, then the right brain, then auto-memory), and after a compaction with a review card (goals and their review days, sections near their caps, anchors that closed, the overflow queue, the last loss score). `brain show ID` prints one item whole, the compact instructions keep the owner's requests verbatim, and the plugin ships a rulebook (`docs/rulebook.md`) that the `brain` skill points to.
- minor: The brain's caps are configuration: `.vibemaestro/brain.json` in the main work tree of the project (every worktree reads it; in a repository whose git directory is kept apart each worktree reads its own, and `brain doctor` says so) sets the live items per section and the text and quote lengths, every key with a default (Pinned 20, Windows 10, Now 5, Sessions 20, Owner queue 15, Next 30, Traps 20, Facts 25; texts 300, a session's 600, the owner's words 600, counted in UTF-16 units as Claude Code counts them); an unknown key warns, a wrong value refuses writes until it is fixed, and a left-brain cap that differs from its default is flagged, since changing it is the owner's decision. A full right-brain section no longer refuses an add: the item waits in that section's overflow queue in the log, one line counts the queues, `brain overflow` lists them, and the close that makes room moves the head up in the same log line; the left brain (pinned decisions and windows) has no overflow, and an owner add at its cap is refused before the dialog asks, naming the items to choose from. SessionStart packs the left brain and the right brain into strings of at most 9,500 UTF-16 units each, the left brain in strings of its own, up to 14 strings, the 14th naming what did not fit. The line under a pin cuts the owner's quote without parting a letter from its marks, a flag, a skin tone or a Hangul syllable.
- minor: A project's brain can be exported, imported and backed up: `brain export --out FILE` writes one bundle (the log line by line with its chain head, the items, the overflow queue and the evidence ledger; this machine's paths as placeholders; the sensitive-value filter over all of it), `brain doctor --bundle FILE` checks one, `brain import FILE` lands its right brain as `brain op add` writes it and replays its ledger, and `brain owner import FILE` lands its goals, decisions and windows through one dialog that lists every one, each keeping the owner's words and a provenance line. A decision may carry `--scope global|project`, set or changed through the dialog by `brain owner supersede D3 --scope global` (its words unchanged); `brain export --scope global` carries only the global goals and decisions. `brain owner backup DIR` names a private backup place; the hooks write a backup there in the background when one is due, and restore is an import into an empty brain.
- minor: Another plugin can extend the brain through one declared script (`brain-extension.json` at its root, run in a process of its own): a check on a `brain op` write, an owner verb through the same permission dialog, lines at session start, on the review card and in the measurement record, and `brain ext NAME`; it never writes the brain, and a missing, broken or slow one is skipped with one line that `brain doctor` explains. The direction gate on session items (`--goal`, `--no-goal`), the drift report a `broke` prints, the promotion of a lesson or a fact to SOUL by its code, `brain owner demote`, the seven-line card and their review-card lines are not part of the brain, which a plugin that extends it may carry: `brain ledger` marks `promote?` and `drift`, `brain owner promote` moves a goal, decision or window out to a pointer, and a log that holds an older brain's goal, demotion or code fields still verifies, folds and renders. An extension's data travels in an exported bundle, and `brain import` does not land it.
- minor: The brain keeps an evidence ledger in its log: `brain op held|broke RULE` (a pinned decision, a trap or lesson, a fact, or a SOUL rule by its code such as `S07`; a broke always says what differed) and a trap's `brain op hit` count when a rule held and when it broke, from which sessions, with a pointer each, and `brain op progress G1` records a goal's progress without changing the goal. `brain ledger` reads it back; a broke that makes a rule drift prints the evidence and three options to report to the owner at once. Each running session names the goal it serves, or the owner's reason for none, which is counted. Promotion, drift and dormancy thresholds are keys of `ledger` in `.vibemaestro/brain.json`, with defaults. `brain owner promote` takes a lesson or a fact straight to SOUL by its code, its evidence following it, after the seven-line card `brain ledger ID --card` prints; `brain owner demote` brings a SOUL rule back as a decision; both go through the owner's dialog. The review card after a compaction adds drift, a line per goal with its progress and sessions, work with no goal, promotion candidates, SOUL rules to review, dormant items and the monthly record due (`brain ledger --record`).
- minor: `brain owner batch FILE` pins, supersedes or unpins 2 to 5 owner items through one dialog. In the writer's session, a prompt runs `brain op close-linked` in the background at most every 10 minutes, so an item whose PR merged closes without a SessionStart. A bare `#N` anchor no longer resolves against another repository. The owner dialog's fields before the text take only plain characters. The render keeps an emoji or a word joined by a zero-width joiner, and a pin's source shows whole. `brain render` prints the precedence line. The review card says when this compaction's loss score is not logged yet, instead of showing the previous one. `brain doctor` stops warning about a session reloaded with `/reload-plugins` once it runs a `brain` command. The CLI works in a project whose path is not UTF-8, and refuses cleanly in a deleted directory.
- minor: A released plugin now requires the version of a sibling it was released with, instead of any version from 0.1.0: `release.py cut` writes `Released together: <plugin> <version>, …` as the first line of each new CHANGELOG section when two or more plugins are released, and the public export writes `>=` that sibling version into the dependent plugin's manifest (a section with no such line keeps `>=0.1.0`, so a version that does not move keeps its manifest). `release.py plan` and `cut` print that line and each raised plugin's new floor; `release.py notes` prints it first, and when a plugin's floor on a sibling moved, its Updating section says to update that sibling too, before or with it.
- patch: The owner's permission dialog for pinning, importing or replacing a decision now names its kind, `Pin owner decision D3 (a lasting direction, never done), …`, and the `brain` skill and rulebook give the test that tells a goal, a decision and a request apart (can it be delivered and closed? then it is a request, not a decision).

### Upgrade notes

- Restart every session of a project on this version before the first goal, focus or request is written: an older brain refuses to write to a log that holds one, and stops injecting whenever it must read that log again.
- Restart every session of a project on this version before the first item is queued: an older brain refuses to write to a log that holds a queued item, and stops injecting whenever it must read that log again. Now, Next and the other working sections move out of string 1 into the right brain's strings, and the default caps grow (a project lowers them in .vibemaestro/brain.json).
- A session is also a worker session when VIBEMAESTRO_ROLE is exactly worker, as when INTENT_SLUG and SEAT are both set: its hooks are silent and its writes stop with rc 4.
- Restart every session of a project on this version before the first held, broke or progress is written: an older brain refuses to write to a log that holds one, and stops injecting whenever it must read that log again.
- `BRAIN_DEFAULT_REPO` is ignored: a bare `#N` anchor is checked only when its item's other anchors or `closes` name exactly one repository, so write `owner/name#N` and remove the variable (`brain doctor` warns while it is set). The owner dialog's source, pointer, done and not-doing fields refuse emoji, right-to-left letters and other characters outside an allowlist. Run `brain render` once, or write anything, so `brain doctor` stops calling `hot.md` an older brain's render.
- Update vibemaestro-sdlc together with vibemaestro-brain: a public brain now requires the sdlc version it was released with, and does not load over an older one.

## 0.2.0

- minor: The brain flags a live Now, Next or pinned item whose anchor is a closed issue, a merged PR or a closed PR. An anchor counts only as a whole `#N` (against the new optional `BRAIN_DEFAULT_REPO=owner/name`) or `owner/name#N`. `brain doctor` looks each one up with `gh` and prints a `warn` per stale anchor (rc unchanged, nothing written). The SessionStart block marks such an item with ` · stale: #7 closed <date>` and adds one note line when `gh` is missing, a lookup fails or times out, or bare anchors are skipped; answers are cached 600 s (a failure 120 s), uncached lookups run in parallel under a 2 s deadline and are killed, and the marks and note add at most 450 characters. A stale mark alone changes nothing: the check writes nothing to the log, head or `hot.md`. The brain closes an item on its own only when it is a Now, Next, session or queue item that named its issues or PRs with `--closes` and every one of them is done (the `--closes` entry below); it never closes or edits an owner item (a pinned decision or a window), and a trap or a fact is closed only by hand.
- patch: `brain matrix` no longer says the repo index is "planned B1.7": B1.7 is built, so the Know·hot row says the index is shared and that sdlc injects it at SessionStart when `current_state.inject` is on.
- minor: A public install says at session start when a newer version of vibemaestro-sdlc or vibemaestro-brain exists: one line with both versions, `/plugin` then `/reload-plugins`, and the release notes link (silent offline, in a sandbox, for an install with no version, or with `VIBEMAESTRO_NO_UPDATE_CHECK` or `update_check: false`); a change file may carry an `upgrade:` line, which a release writes under `### Upgrade notes`, and `release.py notes <plugin> <version>` prints a release's notes.
- minor: The stale-anchor check works in a session that spans several repositories. A GitHub issue or PR URL (`https://github.com/owner/name/issues/N` or `/pull/N`) is now an anchor, checked like `owner/name#N`, neither of which needs BRAIN_DEFAULT_REPO. `brain op add`, `brain op supersede`, `brain owner add` and `brain owner supersede` warn, without refusing, when the item they write carries a bare `#N` and no default repository is set, and print the `owner/name#N` form to use. `brain doctor` lists each live item and anchor it could not check (at most 20 lines, then a count of the rest) instead of only counting them.
- minor: A Now or Next item can name, with `--closes owner/name#N` or an issue or PR URL, the issue or PR whose close means it is done, and the writer session's SessionStart then closes it itself (the op `link-close`, with a reason and a pointer, outside the retirement budget) once that PR is merged into its default branch or that issue is closed as completed, saying so in one note line; a PR closed unmerged or merged into another branch, an issue closed as not planned, a failed or late lookup, another session's start, a pinned decision, a window or a trap never close and keep their mark (`owner retires it` on a pin), more than 5 items at once are held for `brain op close-linked`, and `brain doctor` shows what would close, what closed in the last 24 hours and any reopened issue. Stale marks now say `closed unmerged`, `merged into <branch>` and `closed not planned`, the lookups take the least recently checked anchors first so every anchor is reached, and every `gh` call names `--hostname github.com`.
- minor: A long-running session keeps all its state in the brain: three new kinds, session (a running session's next step with its pointers, up to 12, text up to 450 characters), queue (what waits on the owner, up to 5) and fact (a path or fact in use, up to 5); Next holds up to 10 and Traps up to 13; a pinned decision shows the owner's words under it; and Done, the items closed in the last 24 hours with their anchor and merge commit, is read from the log, never written. SessionStart injects up to three strings, each under Claude Code's 10,000-character cap by its own cut: hot memory and the Shelf index (8,000), sessions and the owner queue (9,500), and Next, Traps, Done and Facts (9,500), the last two left out when empty. Session and queue items can close themselves when their PR merges, and a supersede of one spends no retirement budget.
- patch: The brain keeps a session's own project wherever the shell moves with `cd`: a compaction while the shell is in another repository injects the session's hot memory and logs its episode there, and `brain`, run from another project, uses the session's project and prints one line naming both. The hooks take the project from `CLAUDE_PROJECT_DIR` and record it under the session id in `…/vibemaestro/brain/sessions/`; the CLI reads that record and refuses (rc 1) one it cannot trust. Outside a Claude Code session, the current directory's project, as before.
- patch: The owner-dialog hook acts only on a command that starts with `brain owner` (`brain`, a path to `bin/brain`, or `python3` running `scripts/brain.py`): a Bash call that only mentions the two words, such as a here-document body with an apostrophe or a line `brain owner …`, an `echo` or a `grep`, is no longer refused. A real `brain owner` command is guarded as before, alone, literal or denied, and one run through `bash -c`, `eval` or a here-document fed to a shell is still refused by the CLI.

### Upgrade notes

- The SessionStart block may mark an item ` · stale: #N closed …` and looks anchors up with `gh`; a bare `#N` anchor counts only with `BRAIN_DEFAULT_REPO=owner/name` set.
- A session start may show one line when a newer public version exists, after one background read of the public tags a day per plugin; set `VIBEMAESTRO_NO_UPDATE_CHECK=1` to turn it off.
- A bare `#N` anchor with no BRAIN_DEFAULT_REPO now prints a warning when you write it (the write still succeeds); write `owner/name#N` or a GitHub issue or PR URL instead, which are checked with no setting.
- Restart every session of a project on this version before an item closes by a link: an older brain refuses a log that holds a `link-close` and stops injecting hot memory (`brain doctor` warns about a session that last started an older brain), and going back to an older version is not supported once one is written.
- Restart every session of a project on this version before writing a session, queue or fact item: an older brain refuses to write to a log that holds one, and stops injecting hot memory whenever it has to read that log again (`brain doctor` warns about a session that last started an older brain). Next and Traps now come in the third SessionStart string, `## Brain · plan`, no longer in the hot memory block; `brain render` (or the next write) rewrites hot.md in the new layout.
- A session already running when you update keeps resolving the project from its shell's directory; start a new session to get the fix.

## 0.1.0

- patch: Skill, rule and contract text no longer carries dates, plan-row ids, issue numbers or pointers into the kit's private notes; what each step tells a session to do is unchanged.
- patch: The README describes the plugin as it is now: no plan rows, dates or internal paths, and the dependency on vibemaestro-sdlc without an old version floor.
- minor: No plugin carries a version in the private repo any more (an install follows the commit); the first public release numbers sdlc and brain 0.1.0, and the public tags are `<plugin>--v<version>`.
- patch: The README is written for one person with one Claude seat on one machine: one task or several with local-parallel, who merges, and a worker session named by INTENT_SLUG and SEAT; no other plugin or cluster is needed.
- minor: A session working alone reads a solo core: the coordinator and worker roles moved to the rule coordinated-work, delivered whole only in a sandbox session or where an enabled plugin of the same marketplace ships the marker file sdlc-coordinated; kb.py init records "language" in every new config (en unless answered) and init-kb recommends en; the init-kb branch is chore/kb-init (the old name is still found); the SessionStart hook arguments are core and context (the old ones still work); the BatonRun standard ships in the plugin as docs/batonrun.md; the marketplace description and open-pr.sh's --closes line are English.
- patch: Comments, help text and skill examples no longer point at the maintainers' private notes, issue numbers or dates; behaviour is unchanged.
- patch: `brain` now exits with rc 7 (not 3) when run outside a Claude Code session, so rc 3 only means "another session writes this brain" and the skill's table no longer sends you to `claim --take-over` for nothing.
