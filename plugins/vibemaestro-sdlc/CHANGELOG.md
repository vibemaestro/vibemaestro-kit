# Changelog of vibemaestro-sdlc

Newest first. Each `## <version>` is a public release, written from the change notes it ships; the first public release is 0.1.0.

## 0.1.0

- minor: `kit:merge-pr --behind auto` merges a PR that is behind its base without merging the base first, when GitHub's fresh test merge is clean, every file both sides changed is a docs file that merges clean, and the base's planner (`merge.planner`, run from the base) shows that main's files wake no suite the PR's CI ran.
- minor: A config written for a newer plugin no longer stops an older one: an unknown key in `.vibemaestro/sdlc.json` is a warning (kb.py, the gates and the cores print it once, the hooks once per session) and is ignored, while a known key with a wrong value still refuses; a schema newer than the plugin names the update to run; `kb.py config migrate` carries a config up; the new rule `config-compat` reminds, on the config and its reader, how to add, rename or remove a key and when a new key may be set in a repository.
- minor: The PR gate workflow templates run less, and only where it matters. A new commit cancels the runs of the head it replaces, and no other event cancels or replaces a run. No gate runs on a draft (going ready starts the round), except `pr-sensitive` in a public repository. An edit re-runs only the gates that read what changed: `pr-body` and `pr-sensitive` on a body change, `pr-title` on a title change, `commit-discipline` when the old or the new body holds the exemption token (written in from `tokens.commit_exception` at install). The rule `before-ready` says the related tests and the fresh-context review come before ready. A repository with the gates installed gets the new templates by deleting its gate workflows and installing again (install-gates never overwrites).
- minor: PR bodies no longer carry the flow checklist, whose ticks nothing checked; an older body that still has one passes as before, and `pr.flow` and `pr.tester_exempt` are deprecated (a config that sets them gets a warning). The new gate `pr-evidence` (install-gates installs it) asks for an AI-review round comment pinned to the PR's current head (`SHA: <full head SHA> — review round N`, by a member), and, when the PR changes a path of the new key `evidence.ui_paths`, an `E2E pass` or `E2E không chạy: <reason>` line pinned to the head; evidence pinned to an older head counts only over clean merges of the base (no conflict resolved by hand, the same patch-id), and a member's comment re-runs a red check. It runs only on ready PRs.
- patch: The gate workflows that install-gates installs now read the optional repo variable CI_GATE_RUNNER first (a light runner for the short gate jobs) and fall back to your runner variable, so nothing changes until you set it.
- minor: pr-sensitive no longer reads the digits of a whole commit id as a phone number; the merge guard no longer lets a late skipped run hide a green run of the same check; the session-start skill line names every skill of the plugin; local-parallel says up front that a merge needs a CI check; rule measurement-commands names the wrapped-term and self-matching scan traps; kit:gh-write gains pr-close (pinned to the head); kb.py new and check, the tracking-issue lines of intent-branch, the open-pr gate line and the plugin description print English.
- patch: The kit baton `kit:publish-public` describes the export it publishes as the release rev's tree minus `kb/` and `public.private`, which is what the public export now holds.
- minor: A repository that publishes its tree sets `public.private` in `.vibemaestro/sdlc.json` (the globs that stay private besides `kb/`); the new rule `public-tree` then reminds on an edit outside `kb/` and those globs that the file is public: nothing private, no pointer into `kb/`, no private issue number, tests that run from that tree alone. `applyTo` gains the token `${public.tree}` (a whole glob of its own). The session's rule catalogue no longer lists a rule that can never fire in the repo (its `applyTo` expands to nothing and it has no `applyWhen`).
- patch: Skill, rule and contract text no longer carries dates, plan-row ids, issue numbers or pointers into the kit's private notes; what each step tells a session to do is unchanged.
- minor: New rule docs-final: when a session edits a README, a root doc (DEVELOPMENT, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT) or a file under docs/, it is reminded that these are final public documentation (no dates, history, decisions, kb/ pointers or private names); the README states the current install and release facts.
- patch: The kit baton `kit:publish-public` runs git in its scratch repository with no automatic maintenance: with git 2.54 or later, the background repack a fetch starts in it could race the baton's cleanup and end a finished phase with rc 1.
- minor: No plugin carries a version in the private repo any more (an install follows the commit); the first public release numbers sdlc and brain 0.1.0, and the public tags are `<plugin>--v<version>`.
- patch: On a fresh install the first baton that stops for your signature says the approval mode is not chosen yet, and the session asks you once whether to use auto (recommended on a solo machine: the session signs normal batons, stop-list ones still ask you) or manual; your answer sets it, through the usual mode dialog.
- patch: The baton launcher, a dependent plugin's kit, the coordinator bootstrap and `baton permissions --check` accept a plugin installed from a git-subdir source (its directory is `<12 hex>-<8 hex>`), so batons keep running when a marketplace names sdlc as a git-subdir source; reinstall the launcher (`baton.py permissions --install-launcher`) after the update.
- minor: `kit:<name>` also runs a kit that another installed plugin of sdlc's own marketplace ships in its `batons/`, when that plugin declares the dependency on vibemaestro-sdlc. The plugin registry is read beside the running sdlc copy, never from `CLAUDE_CONFIG_DIR` or `HOME`. Such a kit gets the checks an sdlc kit gets; its signature binds that plugin's `batons/`, and `BATON_PLUGIN_ROOT` is that plugin's root. A name that two plugins ship, a plugin from another marketplace, and a plugin without the dependency are refused before anything runs.
- patch: The README is written for one person with one Claude seat on one machine: one task or several with local-parallel, who merges, and a worker session named by INTENT_SLUG and SEAT; no other plugin or cluster is needed.
- minor: A session working alone reads a solo core: the coordinator and worker roles moved to the rule coordinated-work, delivered whole only in a sandbox session or where an enabled plugin of the same marketplace ships the marker file sdlc-coordinated; kb.py init records "language" in every new config (en unless answered) and init-kb recommends en; the init-kb branch is chore/kb-init (the old name is still found); the SessionStart hook arguments are core and context (the old ones still work); the BatonRun standard ships in the plugin as docs/batonrun.md; the marketplace description and open-pr.sh's --closes line are English.
- patch: Rule `public-tree` names the check that enforces it where a repository runs one, and allows any reserved e-mail domain (`example.invalid`, `.test`, `example.com`).
- patch: The spec and brainstorm skills decide "sandbox session" by the sandbox-env contract (`INTENT_SLUG` and `SEAT` both set and not empty), not by a `session-ask` on PATH; a solo session asks the person directly even when a session-ask is installed.
- patch: The messages of `kb.py`, `intent-branch.sh`, `open-pr.sh`, their cores and the pr-evidence gate follow the repo's `language`: English with `"language": "en"`, unchanged Vietnamese without the key; installed gates print in it once `.vibemaestro/gates/` is deleted and install-gates re-run (it now vendors the message table too).
- patch: Comments, help text and skill examples no longer point at the maintainers' private notes, issue numbers or dates; behaviour is unchanged.
- minor: The kit batons kit:publish-public and kit:release-promote are no longer part of the plugin: the skill release cuts a release, then you publish it your own way; release.py check accepts a pull request that removes a plugin whole, with its marketplace entry and its pending change notes.
- minor: kit:gh-write gains three pull-request ops: pr-ready (a draft at its pinned head marked ready), pr-create (a PR from a pushed branch at a pinned head) and file-pr (one file added or replaced, proposed as a PR on a new branch from the base tip, the replaced blob pinned, authored by the viewer's noreply address; a workflow path is refused); the batonrun docs say a dependent plugin's batons run as kit:<name>.
- patch: init-kb finds the default branch in a repo that was not cloned (`git remote set-head origin --auto` first), and a session in a tree without `kb/` now says when the scaffold is on the unmerged init-kb branch instead of telling you to run init-kb again.

## Private history (numbering retired 2026-10-20)

The numbers below were private and are not public releases; the version count starts again at 0.1.0.

### 2.30.0

- minor: New skill `local-parallel`: on one machine with only vibemaestro-sdlc and vibemaestro-brain, the main session runs several tasks at once as subagents (own worktree each, intake to a draft PR), keeps the queue, post-checks and merges each PR with `kit:merge-pr`; the README names the two ways of working (local, sandbox).
- patch: Declare the Apache-2.0 licence in the plugin manifest (`license` field); the kit now ships a `LICENSE` and `NOTICE` at its root.
- minor: New kit baton `kit:publish-public <release rev>`: publishes a release of the kit to its public repository as one commit with its release tags, only when a green export-gate run dispatched on main scanned exactly that tree; no force, undo deletes only its own tags.
- patch: The plugin now has a README (English and Vietnamese): its skills, gates, rules, config keys, version policy and troubleshooting commands.
- patch: The plugin README (English and Vietnamese) points its "whole kit" reference at the public docs index instead of `docs/features.md`, which is no longer in the public export.

### 2.29.0

- minor: The current-state ledger can be an index plus pages under one flat directory (`current_state.pages`), with a size cap of their own, a check for orphan pages and dead pointers, and `current_state.watch_exclude` for paths that never force a ledger edit.
- minor: `current_state.labels` (a regex with a `date` group, `max_age_days`): a ledger label with no date or older than N days prints a WARNING, and its date is not a history sign.
- minor: `current_state.inject` (off by default): SessionStart `startup` and `compact` inject the repo's current-state index as a string of its own (from `origin/main`, marked, when the tree is behind), with the list of unchecked labels; with it on, an index over 9,000 characters is red.
- patch: The batonrun guidance and the `go -` messages now say to Write a baton to a fresh path and run `go <path>`, because Claude Code blocks a heredoc that holds the baton skeleton.
- minor: A run killed before it prints is found with `baton log --last`, a gh-write comment can be posted on a closed target with `closed_ok`, and `plan status` notes a planned row that a PR title names.
- minor: Releases: `release.py plan` and `cut`, the skill `release`, the baton `kit:release-promote` (moves `release`, tags `<plugin>-v<version>`, opens the back-merge PR of a hotfix), the release, hotfix and back-merge kinds of `release.py check`, and the merge guard merges a `backmerge/*` PR from `release` with a merge commit.

### 2.28.0

- minor: Versions change only in a release or a hotfix: a pull request that changes a plugin adds a `.changes/<slug>.md` file instead, checked by `scripts/release.py check`; the rule `version-policy`, and the plan skill puts `Version` on a feature group's release row only.
