# Changelog of vibemaestro-sdlc

Newest first. Each `## <version>` is a public release, written from the change notes it ships; the first public release is 0.1.0.

## 0.2.0

- patch: The kit's own workflows (the test-full export job included) run on the runner variable CI_RUNNER, gate jobs on CI_GATE_RUNNER first: with neither set, a private repository's run fails at once instead of falling back to a hosted runner, and the public repository still uses ubuntu-latest.
- minor: Two kit batons: kit:branch-push pushes one local branch as a new branch of its private GitHub repository at a pinned tip (never forced, no workflow change, undo names a branch it cannot delete), and kit:workflow-dispatch starts one workflow_dispatch run in a private repository, pinned to the branch head and the workflow file, with an undo that cancels only its own run.
- patch: `kit:merge-pr --behind auto` no longer refuses a PR that is behind its base just because GitHub has not rebuilt its test merge after the base moved: the compare API (the merge base, `behind_by` and the files the base changed since) decides, and the test merge is read only where it still adds information (`mergeable` false is a conflict; a file both sides changed still needs it as the second opinion, and is could-not-conclude while it is stale). A file on one side where the other has a directory of that name, two paths that differ only in case or Unicode form, and a file moved out of a directory (at any level) on one side while the other side has a path in it (a directory rename), now refuse under `--behind auto`.
- minor: `baton sign --by owner` signs only after Claude Code's dialog for that very call: a new PreToolUse hook opens the dialog and writes a one-use record that only the command the dialog runs can use, sign refuses without it and run refuses an owner signature that names none, in a sandbox, from a subagent, in plan, dontAsk, bypassPermissions or a -p run, while a hook or a permission-prompt tool could answer, or while an allow rule matches it; an owner's own `!` line is refused too, so the session runs the printed command right after the decision card.
- patch: An act that `check` refused, or that waits for the owner (exit 8), is never done by another route, and a check that passes is not a yes: the batonrun rule, skill and `limits.md` now say so plainly. `check` flags a ref deleted without being declared as `irreversible-delete`: `git update-ref -d` or a zero new value, an `update-ref --stdin` delete line or one fed by a heredoc or a file, a `:<ref>` push refspec quoted or forced (with or without `--force-with-lease`), `git branch -D` and `git tag -d` in any repository, `git branch -d` or a forced branch write pointed at another repository (`-C`, `--git-dir`, `--work-tree`, `GIT_DIR=`), a refs path removed or truncated, and a write to `packed-refs`; git's `-p|-P` no longer hide a subcommand. A ref created or moved with `update-ref` stays unflagged. The stop list's `irreversible-delete` now names branches and tags, not only unmerged ones: check cannot prove a branch merged, so a hand-written branch or tag delete needs the owner. The rule's reminder also fires on a bare ref delete (`git push --delete` or `:<ref>`, `update-ref -d`, a zero value or `--stdin`, `branch -D`, `tag -d`).
- minor: `kit:branch-delete` also deletes a squash- or rebase-merged branch (`kit:merge-pr` squashes). When the branch SHA is not an ancestor of the base head, it looks in GitHub's own list of closed pull requests from this repository's branch into the base for a merged one whose head is the branch SHA now, whose merge commit is on the base head, and whose `refs/pull/<n>/head` is at that SHA (so the commits stay reachable and undo can recreate the branch); candidates are tried from the lowest number up, and the number is never an argument. The plan line names the proof (`ancestor` or `merged PR #<n>`, since a squash and a rebase merge cannot be told apart), and the post-check and undo re-prove the same proof. A PR merged into another base, a fork's PR and a branch pushed after its merge are refused, as is everything the kit refused before.
- minor: New kit baton `kit:branch-delete`: deletes one branch of a private GitHub repository that is merged into its base, with no owner signature (`Stops: none`). Run from a clone: `go kit:branch-delete --repo <owner/name> --branch <name> [--base <name>] [--remote <name>]`. Rehearse proves from GitHub that the branch's SHA is an ancestor of the base head (compare API) and pins the branch, its SHA, the base and the base SHA in the plan line; the delete pushes with a lease on that SHA, so a branch that moved is not deleted; undo recreates the branch at the deleted SHA. The base must be the default branch or a protected one; the post-check proves the base still holds the SHA, and undo recreates the branch only when a run record says this run's delete landed (a failed push with the branch gone is an unknown outcome: undo puts the branch back when its base no longer holds the SHA, else leaves it for the owner). It refuses an unmerged branch (a squash- or rebase-merged one included), a default, base or protected branch, one a ruleset forbids to delete, a name that is also a tag, an open pull request from or into the branch, and a public or internal repository. Every API call names github.com. The stop list and `check`'s message for a flagged branch delete now point to it for a merged branch; unmerged branches and tags still need the owner.
- minor: For an organisation that runs only self-hosted runners, `ci.runner_default` can now be `"self-hosted only"`: the workflows that install-gates writes then name no hosted fallback, and a run with the runner variable unset fails at its start with a message naming the variable instead of staying queued for a machine that never comes; the default stays `ubuntu-latest`.
- patch: The README line on the sdlc study now states its scoring ("0.76–1.25 under the scoring fixed before the last task ran"), and the research page says what the study measured and what it did not.
- patch: A baton `path`, `under:`, `file` or `input` value (and the path of a `url`) may now have a middle segment that starts with `-`, `+` or `@`, so a file written in Claude Code's scratchpad (`/tmp/claude-<uid>/-home-…/scratchpad`) can be passed; a value whose last segment starts with one is still refused.
- minor: Every line `baton` prints goes through one print path: a value baton did not write itself (a path, a name, a header field, an argument, an error) has its control and format characters written `\u{…}`, so no value can start a line of baton's own such as `owner:`. A line a baton script prints is relayed under two spaces with its control characters escaped, on stdout and in the run log (`  PLAN …`, `  VERDICT run ok`): a reader of baton's output that matched `^PLAN ` now matches `^  PLAN `. The plan file a script gets (`BATON_PLAN`), the writes file and `log.tsv` are unchanged.
- patch: baton: a stop signal (Ctrl-C, a closed terminal, a tool timeout), or a few at once, that arrives while baton starts a phase now stops what that phase started, as one a moment later does.
- minor: A baton can declare `# Params: key=type …` and be called with `key=value` words: every value is checked against its type (int, sha40, sha256, name, repo, ref, path, `under:<dir>`, url, file, input, `enum:`; free text goes through an input file) before anything runs, reaches the script as `$1…` in the declared order (read once into `P_<KEY>`), and is bound by the signature; a file value runs as a read-only copy bound by its sha256. `check` refuses a baton that lets a value reach a shell unquoted, become a command, an option of `gh -F` or `curl -d`, or text in a here-document, and a script holding a NUL byte; a `<<` in an assignment subscript is no longer read as a here-document that hides the next lines from the lints. New places: `project:<name>` (`<project root>/.vibemaestro/batons/<name>.sh`) and `user:<name>` (the user library) run only with bytes a keep record pins, with no 120 s gate; any other prefix and a bare name are refused (rc 64). New `baton list [<keyword>…]`: a bounded catalogue of kits, kinds and kept batons, with run counts, or the whole entry of the one baton that matches. Kits and callable kinds now carry a `# Usage:` line, and `check` refuses a kit that has neither Usage nor Params. `log.tsv` gains a last field, `baton` (`<prefix>:<name>@<sha256>`). Text baton prints from a file or a value has its control and format characters written `\u{…}`.
- minor: New `baton pack <script> <project|user>:<name>`: keeps a script that ran ok on this machine (an `ok` run of these exact bytes in its own `log.tsv`) as a kept baton, so `go <place>:<name> key=…` runs it at once. It checks the bytes as a kept baton of that place, writes the file through a temporary file and a rename (a link at the target is replaced, never followed), and writes a keep record under a per-place lock that ends with its process, with a sequence number no two writers share. It refuses a name a kit or callable kind ships, a copy name (`-v<digits>`, `-<7 or more hex>`), the same bytes under another name in that place, and another `Stops`. A `user:` keep prints one `owner:` line to relay. A name ending in a newline is refused, here and by `go`. `baton pack <place>:<name> <other place>:<name>` moves a kept baton between `project:` and `user:` and leaves no pinned copy; the same command finishes a move that was cut. `baton pack --retire <place>:<name> <sha256>` unpins one sha. `pack` is allowed in the permission rules `permissions --print` writes.

### Upgrade notes

- `baton sign --by owner` now needs Claude Code's permission dialog for that very call: sign in an interactive session; a `!` line, a subagent, a `-p` run or a matching allow rule is refused.
- `baton check` now flags a branch, tag or ref delete not declared as `irreversible-delete`, and such a baton needs the owner's signature: run `baton check` on your own batons.
- Lines a baton script prints now come under two spaces: a reader of baton's output that matched `^PLAN ` must match `^  PLAN ` (and `^  VERDICT `).
- `baton` refuses a bare name or an unknown prefix (rc 64): call a kept baton as `project:<name>` or `user:<name>`, and run `baton check` on your own batons, since it refuses more.
- After an update, restart Claude Code when the SessionStart line says the session runs another vibemaestro-sdlc than the installed one.
- A config that already sets `merge.deny_globs` keeps its list: add `.vibemaestro/<dir>/**` for each `rules.dirs` folder yourself.
- An Edit, Write or Bash call that adds an allow rule or loosens a Claude Code settings file is now denied: make permission changes through kind:settings-merge, which the owner signs.
- A session start may show one line when a newer public version exists, after one background read of the public tags a day per plugin; set `VIBEMAESTRO_NO_UPDATE_CHECK=1` to turn it off.
- Run `<launcher> go kit:permissions-upgrade` once (the owner signs): it swaps the old ask rules in your user settings, which `permissions --check` now names as STALE. A mode change (`mode auto`, `mode manual|trust|untrust`) now needs the owner's dialog through the plugin's hook and is refused without it (rc 3), a `!` command in the prompt included: the session runs the command the card's `Mode:` line prints (the launcher or this plugin's `baton.py` by its absolute path) alone in its Bash call, and the owner clicks. A mode or remote list set before this version reads as not chosen: an owner in auto confirms the mode once more (one dialog) and trusts the remote list again.

## 0.1.0

- minor: `kit:merge-pr --behind auto` merges a PR that is behind its base without merging the base first, when GitHub's fresh test merge is clean, every file both sides changed is a docs file that merges clean, and the base's planner (`merge.planner`, run from the base) shows that main's files wake no suite the PR's CI ran.
- minor: A config written for a newer plugin no longer stops an older one: an unknown key in `.vibemaestro/sdlc.json` is a warning (kb.py, the gates and the cores print it once, the hooks once per session) and is ignored, while a known key with a wrong value still refuses; a schema newer than the plugin names the update to run; `kb.py config migrate` carries a config up; the new rule `config-compat` reminds, on the config and its reader, how to add, rename or remove a key and when a new key may be set in a repository.
- minor: The PR gate workflow templates run less, and only where it matters. A new commit cancels the runs of the head it replaces, and no other event cancels or replaces a run. No gate runs on a draft (going ready starts the round), except `pr-sensitive` in a public repository. An edit re-runs only the gates that read what changed: `pr-body` and `pr-sensitive` on a body change, `pr-title` on a title change, `commit-discipline` when the old or the new body holds the exemption token (written in from `tokens.commit_exception` at install). The rule `before-ready` says the related tests and the fresh-context review come before ready. A repository with the gates installed gets the new templates by deleting its gate workflows and installing again (install-gates never overwrites).
- minor: PR bodies no longer carry the flow checklist, whose ticks nothing checked; an older body that still has one passes as before, and `pr.flow` and `pr.tester_exempt` are deprecated (a config that sets them gets a warning). The new gate `pr-evidence` (install-gates installs it) asks for an AI-review round comment pinned to the PR's current head (`SHA: <full head SHA> — review round N`, by a member), and, when the PR changes a path of the new key `evidence.ui_paths`, an `E2E pass` or `E2E không chạy: <reason>` line pinned to the head; evidence pinned to an older head counts only over clean merges of the base (no conflict resolved by hand, the same patch-id), and a member's comment re-runs a red check. It runs only on ready PRs.
- patch: The gate workflows that install-gates installs now read the optional repo variable CI_GATE_RUNNER first (a light runner for the short gate jobs) and fall back to your runner variable, so nothing changes until you set it.
- minor: pr-sensitive no longer reads the digits of a whole commit id as a phone number; the merge guard no longer lets a late skipped run hide a green run of the same check; the session-start skill line names every skill of the plugin; local-parallel says up front that a merge needs a CI check; rule measurement-commands names the wrapped-term and self-matching scan traps; kit:gh-write gains pr-close (pinned to the head); kb.py new and check, the tracking-issue lines of intent-branch, the open-pr gate line and the plugin description print English.
