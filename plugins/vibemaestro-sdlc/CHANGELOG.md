# Changelog of vibemaestro-sdlc

Newest first. Each `## <version>` is a public release, written from the change notes it ships; the first public release is 0.1.0.

## 0.7.4

Released together: vibemaestro-sdlc 0.7.4, vibemaestro-brain 0.5.3

- patch: The session that queued a run for the owner can now have it signed right there: `sign --by owner --queued <id>` from that session (also after `/clear`) opens the same owner dialog with the item's card, as for a direct sign, and `run --queued <id>` then runs it. No second Claude Code session is needed. Every other check of a queued item stays as it was.

## 0.7.3

Released together: vibemaestro-sdlc 0.7.3, vibemaestro-brain 0.5.3

- patch: Everyday mode: turning the kit off in a subfolder (`"hooks": "off"` in its `.vibemaestro/sdlc.json`) now works even when a folder above it holds the save history: the kit stays quiet there, its update reminder included, and the quiet saves leave that subfolder out. When your folder's saves go into the history of a folder above it, Claude tells you once which folder that is.
- patch: When the kit's permission rules on your computer are out of date, the session start no longer shows you a line in English with a command to run: Claude tells you in your own language and offers to fix them with one approval. The same goes for the note that asks you to restart Claude Code after a plugin update.
- patch: The owner can now sign waiting runs (`/vibemaestro-sdlc:owner-sign`) and change the baton's mode in Claude Code's VS Code extension and the Claude desktop app, as in a terminal; not on Windows yet. In `auto` mode this needs Claude Code 2.1.211 or later; when the version cannot be read, the refusal says what was tried and that the default permission mode works. Any other program that could answer the permission dialog is still refused.
- patch: On Windows the baton no longer stops with `No module named 'fcntl'`: the brain can now close or supersede a focus there, and the baton's log, list and mode views work. Signing and signed runs (a merge, the owner's signature) do not run on Windows yet: each says so in one line and runs nothing; they run on Linux and macOS.

## 0.7.2

Released together: vibemaestro-sdlc 0.7.2, vibemaestro-brain 0.5.1

- patch: On Windows the kit no longer goes silent when a message holds a character the machine's code page lacks: a developer session gets its process again, a rule written in Vietnamese blocks again, the kit's commands print Vietnamese without an error, and removing an old copy that holds a read-only file works instead of stopping with an error.

## 0.7.1

Released together: vibemaestro-sdlc 0.7.1, vibemaestro-brain 0.5.0

- patch: In everyday mode the session start shows the person no line in a fixed language: the mode, why and how to switch, and a quiet save that did not keep the work, go to Claude, which says them in the person's own language when it matters. Claude offers the notebook at the first piece of work worth keeping and keeps where the work stands and the person's preferences (`kb/preferences.md`) in it.

## 0.7.0

Released together: vibemaestro-sdlc 0.7.0, vibemaestro-brain 0.5.0

- minor: Everyday mode, for ordinary work that is not a software project: Claude talks in plain words and keeps your notes in a notebook folder (kb/); your folder is saved quietly after each turn, on this computer only; the history skill brings back an earlier save as a copy in a ban-cu/ folder and never writes over your work; it is made to run on Windows and in VS Code too (the README has a Windows / VS Code section; Windows is not tested yet) and says in one line when Python or Git is missing. A folder that is not a git repository, or one the kit created, gets this mode; a folder that already had git, or one connected to GitHub, gets the developer mode; the folder's `profile` setting overrides both.
- minor: The brain learns from merged work: each pull request the merge guard merged counts for the rules and traps its body names (`Rules applied:`, `Traps met:`); `brain ledger --drift` lists the rules drifting with nobody on them, and a promoted SOUL code unused for 30 days shows as dormant; with `soul_file` set, the review card names where the SOUL file and the brain differ, and the owner's SOUL step can carry its line (`brain owner promote … --soul-line`), which the new kit baton `kit:soul-line` adds to that file.
- patch: Merging is safe when GitHub fails part way: `kit:merge-pr` and `kit:owner-merge` no longer take a server error, a timeout or a dropped connection as a refusal; they read the pull request back, count it merged when it merged at the signed head and base, try once more when it is still open, else stop and say the state is unknown; the undo then leaves a merge at the signed head to the owner instead of advising a revert, and `kit:owner-merge` keeps a merge that may still land in its undo record until the run settles it.
- minor: `kb.py check intent` checks a story's shape: each open question says why it exists, what each option means, its impact and the recommendation, and the asker's words map to the AC; an AC not written as when … then, or an unexplained short code, only warns.

### Upgrade notes

- A session in a folder that is not a git repository now gets the everyday mode instead of the developer process; set "profile": "developer" in .vibemaestro/sdlc.json, or VIBEMAESTRO_PROFILE=developer, to keep the developer process there. On a machine without Python the hooks no longer fail one by one: the session gets one line saying what is missing.
- A story new or changed now needs four labelled parts per open question and a words → AC part; `kb.py new intent --type story` writes both, and a story already merged and unchanged only warns.

## 0.3.0

- patch: `baton check` now flags a write onto a Claude Code settings file as stop category `security-boundary`. This covers `settings*.json` under `.claude`, under `$CLAUDE_CONFIG_DIR`, in the managed directory, or under a variable named for `claude`. The shapes are the settings guard's Bash shapes, the path as an argument of `write` or of an interpreter with a heredoc program, and the path held in a variable. A baton declared `Stops: none` that widens the settings no longer passes check. `kind:settings-merge`, `kit:coordinator-bootstrap` and `kit:permissions-upgrade` still check clean, and `skills/batonrun/limits.md` lists what is flagged and what is not seen.
- patch: BatonRun no longer copies a secret: a `file` or `input` Param whose bytes look like key material (a private-key header, a `client-key-data` field, a token of a known shape) is refused before anything is copied or run, and the message names the safe way, a `path` Param the script reads where it is.
- patch: A session that continues an intent whose spec is already approved (a plan row's second PR, a run PR after a spec PR) now sends the `code` stage at its first code step, so a dashboard no longer shows it at `spec` for the whole build: the `spec` skill holds the rule, and the `plan` skill's worker step and `local-parallel` task briefs point at it.

Every other PR against such a base is still refused with rc 65.
- minor: Outside a sandbox, `scripts/stage-signal.sh` now records each intent's stage, the question (`ask`), the done report (`done`), progress steps and a subagent's binding (`bind`) in a local state file under `~/.local/state/vibemaestro/sessions/` for a dashboard to read; `local-parallel` subagents and their main session use it, and the file is the new `CONTRACT.md` item `local-state`. In a sandbox nothing changes.
- patch: `install-gates` writes English-only `sdlc_config.py` and `messages.py` (and no Vietnamese letter in any installed file) when the repo's `language` is `en`, and stops with rc 65 if one is left; with `vi` the copies keep the same code and text.
- patch: BatonRun leaves no copy of a file or input value for a call that never runs (a `go` that stops for the owner, a refused run, a rehearse, a sign, a queued item), and `kind:settings-merge` removes its backup of the settings file once the run held or its undo put the file back; the backup stays only when the state is unknown, for the owner.

- minor: pr-evidence counts a round comment the repository's own GitHub App posts (`evidence.trusted_app`), and that App's comment re-runs a red check (`PR_EVIDENCE_APP`); unset, the gate decides as before.

### Upgrade notes
