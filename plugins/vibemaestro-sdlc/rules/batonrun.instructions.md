# BatonRun: a write flow is one run, kept and called by name

This command writes outside the session. A **simple write** (one comment, one ticket) goes on directly: one step, reversible by one direct call that is not on the
stop list, not on the stop list itself, not a flow met before; never split a flow into such writes. Anything else is one **run** of a baton script
through the launcher `~/.local/state/vibemaestro/baton/bin/baton` (SessionStart names it when it lies elsewhere; until installed: `python3 <root above rules/>/scripts/baton.py`), never typed command by command, never handed to the owner as lines. What a run is: the plugin's `docs/batonrun.md`; how: skill `batonrun`.
1. `list <keyword>`. One fits (purpose, targets, risk): `go <prefix>:<name> key='value'…`, or a kit or kind with the flags its entry shows. Values
   single-quoted; free text from outside (a title, a message) goes into an `input` file written with the Write tool, never on the command line.
2. Close: evolve it in place, never a copy. None: Write a script (header, `Params`, `write()` gate) to a fresh path and `go` it in the same response, never in a heredoc on `go -` (Claude Code blocks it): one `PLAN` line per write against `Expect`, carrying what was read before the act, never a value the act moves.
   Met a second time: `pack <path> project:<name>` (or `user:`); copy any `owner:` line it prints into your next reply to the owner.
3. The session confirms a normal baton itself (mode `auto`, `Stops: none`). A big risk (a stop-list script, or mode `manual`): a decision card (seven short lines, the owner's language), the script, the rehearse
   output, then `sign --by owner --seal <seal> …` in a dialog. A session never signs as the owner: exit 8 means stop, show the card, then run the printed `sign` once, alone (the plugin's hook opens the dialog); in a sandbox pod `go` prints a hand-off instead (pack as `project:`, open the PR, hand the coordinator the call): no `sign`, no `--queue`; never unprompted, as a test, after a refusal or a rejected dialog, or another way. The owner away (not in a pod): `go --queue` in place of `go`, and go on.
4. `run`: only signed (bytes, values, directory, environment, plan); post-check; undo compares every target with its before-state, or `Undo:` names what it leaves; `log` is the audit line. `mode` changes always ask.
5. Never another route: an act check refused, or one waiting for the owner (exit 8), is not done by another command, a file or ref edit, a second script or another tool; report, wait. A passing check is not a yes: `Stops:` says what the act does (a branch, tag or ref deleted anywhere is `irreversible-delete`).

Run the launcher bare, one command per call: no `cd … &&`, no pipe after `sign`, `run` or `go`; set the directory first. A compound
command matches no permission rule, so the classifier decides. A Kubernetes write is a baton the owner signs and the session runs.
Limits: one reminder per session, not a block, on the command line (not `baton.py run` or a command in a variable); baton guards
against slips, not forgery. Also, its hook warns on EVERY launcher `sign`, `run` or `go` sent with a pipe, chain or redirect.
